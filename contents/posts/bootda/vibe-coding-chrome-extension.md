사람인, 잡코리아, 원티드에서 지원하다 보면 내가 어디에 언제 지원했는지 확인하려고 사이트를 하나씩 다시 열게 된다. 지원한 회사와 공고, 지금 상태를 한 화면에서 보고 싶어서 바이브 코딩으로 **붙다(BootDa)**라는 웹앱을 만들었다. 지원 내역을 직접 입력해서 관리할 수 있게 했고, 웹앱은 Vercel에 배포했다. [붙다 웹앱](https://bootda.my)

그런데 이미 채용 사이트에 있는 지원 내역을 쓰려면 결국 다시 복사해야 했다. 이 부분도 줄이고 싶어서 크롬 확장 프로그램을 붙였다. 확장은 내가 로그인한 브라우저에서 지원 내역을 읽어오고, 웹앱은 가져온 기록을 한곳에서 관리한다. 웹앱을 만들면서 시작한 일이 브라우저에 설치하는 프로그램을 배포하는 일로 이어졌다.

## 내 브라우저에서 돌아가는 것부터

처음에는 `chrome://extensions`에서 개발자 모드를 켜고, `manifest.json`이 있는 폴더를 그대로 불러오면 됐다. 코드를 고친 다음 확장을 새로고침하고, 채용 사이트에 로그인한 상태에서 수집이 되는지 확인하는 식이었다.

같은 지원 내역이라도 사이트마다 화면이 달랐다. 원티드에서는 목록만 읽으면 공고 링크를 얻을 수 없어서, 회사명을 눌러 상세 창을 열고 링크를 읽은 뒤 닫는 동작까지 수집 과정에 넣었다. 상세 창이 뜨는 타이밍과 다음 페이지로 넘어가는 조건도 실제 화면에 맞춰야 했다. 이 부분은 AI와 코드를 빠르게 고칠 수 있어도, 브라우저에서 무엇을 봐야 하는지는 직접 확인해야 했다.

## ZIP을 공유하는 것과 스토어에 올리는 것

GitHub Releases에 ZIP을 올리면 다른 사람도 받아서 설치할 수 있다. 다만 설치하는 사람도 압축을 풀고 개발자 모드에서 폴더를 불러와야 한다. 웹앱은 링크 하나로 열 수 있는데 확장에는 설치 절차가 따로 있었다. 그래서 Chrome 웹 스토어 배포까지 해봤다.

스토어에는 `manifest.json`이 ZIP의 최상위에 오도록 패키징해서 올린다. 개발자 대시보드에서는 스토어에 표시할 소개와 이미지, 확장이 다루는 데이터에 관한 정보를 작성한 뒤 심사를 요청한다. 붙다는 로그인한 채용 사이트에서 지원 기록을 읽어오는 기능이 있어서, 어떤 사이트에 접근하고 읽은 기록이 어디에 저장되는지 설명하는 것도 배포 준비의 일부였다. [Chrome 웹 스토어 게시 가이드](https://developer.chrome.com/docs/webstore/publish)

## 수정할 때마다 다시 올릴 수 있게

확장을 고칠 때마다 같은 순서로 배포할 수 있도록 GitHub Actions에 릴리스 흐름을 만들었다. `manifest.json`의 버전을 올리고 릴리스 노트를 적은 뒤, 머지된 커밋에 `extension-vX.Y.Z` 태그를 푸시한다. Actions는 태그와 manifest의 버전이 같은지 검사하고 ZIP을 만들어 GitHub Releases에 올린다. 스토어 제출을 켜두면 같은 ZIP을 Chrome 웹 스토어 API로 업로드하고 심사를 요청한다. 스토어에서 공개되는 시점은 심사 결과에 달려 있다. [Chrome 웹 스토어 API 가이드](https://developer.chrome.com/docs/webstore/using-api)

웹앱과 확장을 같이 수정할 때는 두 배포의 타이밍도 생각해야 했다. Vercel에 새 웹앱을 올린 뒤에도 사용자의 브라우저에는 이전 확장이 설치되어 있을 수 있다. 실제로 릴리스 노트에 이전 웹앱에서도 수집과 저장이 동작하도록 호환성을 보완한 기록이 남아 있다. 앞으로 두 쪽에 걸친 기능을 추가할 때는 한쪽만 먼저 바뀐 상태에서 무슨 일이 생기는지도 같이 확인해보고 싶다.

## 반에 공유했는데 회원가입부터 막혔다

붙다를 SSAFY 반에 공유했는데 회원가입부터 되지 않았다. 그 일로 강사님께 혼났다. 지원 내역을 가져오는 기능까지 만들어뒀는데, 처음 들어온 사람은 가입에서 막혀 그 기능을 써볼 수도 없었다. 내가 만든 기능을 확인하는 동안 처음 쓰는 사람이 어디서부터 시작하는지 놓쳤다는 게 크게 느껴졌다.

가입 문제를 돌아보면서 Supabase Auth의 이메일 발송 제한도 알게 됐다. 기본 메일 발송 서비스를 쓰면 가입 확인이나 비밀번호 재설정에 필요한 인증 메일을 프로젝트 전체에서 한 시간에 두 통까지만 보낼 수 있다. 혼자 새 계정 하나로 가입을 확인해도, 반에 링크를 공유해 여러 사람이 한꺼번에 가입하면 금방 한도에 걸릴 수 있었다.

백엔드를 같이 맡아줄 사람을 구해야겠다는 생각도 들었다. 가입과 로그인처럼 서비스에 들어오는 첫 단계부터 같이 살펴볼 사람이 있으면 좋겠다고 느꼈다. 다음에 누군가에게 링크를 공유하기 전에는 배포된 사이트에서 새 계정으로 가입하고, 지원 기록 하나를 저장하는 데까지 직접 해봐야겠다.

## ChatGPT Codex 토큰이 다 떨어지니 내가 할 수 있는 게 없었다

처음부터 끝까지 Codex를 사용했고, 컴퓨터 사용 스킬로 어지간한 등록 프로세스, 직접 등록해야하는 것들도 내가 직접하지 않고 Codex를 사용하니 토큰이 떨어지고 난 이후에는 내가 개발할 수 있는 것이 아무 것도 없었다.
